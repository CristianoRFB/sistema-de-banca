ESTRUTURA FIREBASE / FIRESTORE — REFERÊNCIA CANÔNICA
================================================

OBJETIVOS
- Firestore armazena dados estruturados e históricos.
- Firebase Authentication protege administrador; cliente mantém UX sem cadastro tradicional.
- Firebase Storage NÃO é requisito da V1.
- Dados históricos usam status/arquivamento em vez de DELETE rotineiro.
- Operações críticas devem manter invariantes de quantidade e concorrência.

REGRAS DE SEGURANÇA / IMPLEMENTAÇÃO
1. Baseline deve ser deny-by-default até as regras reais estarem implementadas/testadas.
2. Admin autenticado só acessa/modifica a banca autorizada.
3. Público pode ler apenas dados publicados necessários ao catálogo e perfil público da banca.
4. Público não pode listar clientes, sessões, movimentações, históricos administrativos ou telefones completos.
5. Cliente não pode alterar arbitrariamente clienteId/reservaId de outra pessoa. A estratégia técnica deve ser segura mesmo que a UX não exija senha/OTP.
6. Reserva da última unidade deve usar transação/controle de concorrência.
7. Confirmar retirada deve atualizar ItemReserva/Reserva, quantidades, movimentação e histórico de forma atômica ou compensável.
8. Cancelar/expirar deve liberar quantidade de forma atômica e idempotente.
9. Confirmar recolhimento/ajustes deve preservar saldo >= 0 e gerar movimentações.
10. Não armazenar service accounts, private keys ou secrets no frontend/Git.

GUARDRAILS DE CUSTO
- Sem Firebase Storage na V1.
- Evitar snapshots/listeners globais em coleções grandes.
- Paginar histórico e catálogo; limitar queries.
- Evitar N+1 reads; usar snapshots/desnormalização controlada quando reduzir leituras.
- Não criar um documento gigante com toda a lista; itens separados.
- Não armazenar binários/exportações/arquivos OCR no Firestore.
- Índices apenas para consultas reais; revisar `firestore.indexes.json`.
- Jobs agendados devem consultar janelas relevantes e ser idempotentes, não varrer o banco inteiro sem filtro.

ÍNDICES PROVÁVEIS (validar conforme queries reais)
- itensReparte: bancaId + status + publicadoEm desc
- itensReparte: bancaId + reparteId + status
- listas: bancaId + status + publicadaEm desc
- reservas: bancaId + status + dataRetiradaPretendida
- reservas: clienteId + status + criadaEm desc
- notificacoes: destinatarioTipo + status + agendadaPara
- recolhimentos: bancaId + status + dataPrevista
- historico*: bancaId + data/confirmadaEm desc
